## 1. Overview & Problem Statement

The **v1.7.0 release** of `AVAS Routing SW` executes a major architectural evolution driven by reverse-engineering (REA) insights from `Dual Link SDVoE Tester V1.16` (`REA_Reports/`), empirical field diagnostics, and operator ergonomic feedback:

1. **Video Preview Pipeline Modernization (REA Reports 01 & 06)**:
   - In shared multicast environments where multiple AVAS encoders transmit to group `225.1.1.0:5000` (or dynamic pool groups), socket contention previously risked cross-device datagram collisions.
   - In `UnifiedRtpDemuxReceiver`, an early **Source-IP Whitelist Filter** was introduced at the UDP socket boundary (port 5000), immediately dropping packets from unmonitored transmitters before allocating scanline buffers, parsing RFC 4175 headers, or invoking the Q10 rasterizer.
   - Stream control incorporates clean dual-path acquisition: in-band MCU UART commands (`set rtp igmp <IP>\r\n` + `set rtp ON\r\n`) with fallback to standard BlueRiver thumbnail commands (`set <MAC> thumbnail` + `start <MAC>:thumbnail:0`).

2. **Hardware Reset, MCU Reset, and Reboot Fixes (REA Report 03)**:
   - In prior releases, MCU reset and factory default operations failed to trigger because commands were transmitted without mandatory trailing carriage return/line feed (`\r\n`) characters required by the microcontroller's UART command parser. Furthermore, operations failed if Telnet was unauthenticated or dropped.
   - Maintenance was bifurcated into distinct domains:
     - **MCU Domain**: MCU Soft Watchdog Reboot (`set system reboot\r\n`) and MCU EEPROM Factory Reset (`set factory default\r\n`) with REST `/api/device/{mac}` and Telnet `send <MAC> rs232:1 ...\r` dual fallbacks.
     - **BlueRiver AVP PHY Domain**: BlueRiver Silicon Reboot (`reboot <MAC>`) and BlueRiver Node Factory Reset (`factory <MAC>`) with REST `POST /api/device/{mac}` fallback.
     - Independent chip targeting (`Chip 0`, `Chip 1`, `Both`) with user confirmation safety barriers.

3. **Complete Purge of VEGA-1100 Support**:
   - Field testing and reverse engineering established that the experimental VEGA-1100 transceiver does not support the required firmware API hooks and is non-functional in this architecture.
   - Stripped all VEGA constants, predicates, config toggles, and test suites across the solution, returning the codebase to 100% strict AVAS-223 chip_0 focus.

4. **UI/UX Polish — Minimalist Preview Cards (Impeccable & UI-UX-Pro-Max)**:
   - Cleaned up the preview card interface to eliminate cognitive clutter for normal operators.
   - Stripped the "Diag" button, the "chip_0 (TX)" label, and the activation badge.
   - Dedicated link mode badge showing strictly:
     - **`Single Link`** (Muted Slate `#475569`, bold white text)
     - **`Dual Link`** (Vibrant Cobalt Blue `#2563EB`, bold white text)
   - Streamlined 2-line card footer: `IP: <UnicastIp>` and `MAC: <MacAddress>` with a 1-click clipboard copy button, accompanied by a live rolling FPS badge (green $\ge 1.0$, amber $< 1.0$).

5. **Technician PIN-Protected Advanced Settings (`00000000`)**:
   - **Operator Mode (Default)**: Normal operators only see two tabs in the sidebar: `[ Previews ]` and `[ Multi-Link ]`. Thermals and Hardware Diagnostics are completely hidden.
   - **PIN Authentication**: Accessible in the **⚙ Settings** dialog under "Advanced Settings (Technician Access)". Entering PIN **`00000000`** (8 zeros) unlocks the session.
   - **Dynamic `[ ⚙ Advanced ]` Tab**: When unlocked, reveals a 3rd sidebar tab hosting both `Thermals & Telemetry` and `Hardware Diagnostics & Maintenance`, complete with a `🔒 Lock` button for immediate session relocking.

6. **Permanent Modern Default Network Configurations (v1.7.0+)**:
   - **Default Multicast IP Range**: Updated to **`225.0.0.1` to `225.0.1.254`** (510 discrete stream addresses, Class D validated, non-conflicting with Semtech core control space).
   - **Default REST API Port**: Updated to **`8080`** (replaces legacy `8090`).
   - **Configuration Migration**: `ConfigService.cs` automatically detects and migrates legacy defaults (`224.1.3.1`–`224.1.3.225` and port `8090`) to the new standards while preserving custom user overrides.

### 2.3 Socket-Level Source IP Filtering (`UnifiedRtpDemuxReceiver.cs`)
```csharp
// Extract remote IP from UDP datagram
string senderIp = result.RemoteEndPoint.Address.ToString();

// Early whitelist check against active channels and registered companion aliases
if (!_channels.ContainsKey(senderIp) && !_aliases.ContainsKey(senderIp))
{
    // Discard packet immediately at the socket boundary without buffer allocation
    Interlocked.Increment(ref _unmatchedPacketCount);
    continue;
}
```

### 2.4 PIN Lock State Model (`MainViewModel.cs`)
```csharp
public const string DefaultAdvancedPin = "00000000";

public bool IsAdvancedUnlocked
{
    get => _isAdvancedUnlocked;
    set
    {
        if (SetProperty(ref _isAdvancedUnlocked, value))
        {
            OnPropertyChanged(nameof(IsAdvancedTabVisible));
            OnPropertyChanged(nameof(IsAdvancedTabSelected));
        }
    }
}

public bool UnlockAdvancedSettings(string pin)
{
    if (string.Equals(pin?.Trim(), DefaultAdvancedPin, StringComparison.Ordinal))
    {
        IsAdvancedUnlocked = true;
        return true;
    }
    return false;
}

public void LockAdvancedSettings()
{
    IsAdvancedUnlocked = false;
    if (_selectedTab == SidebarTab.Advanced || _selectedTab == SidebarTab.Temperature || _selectedTab == SidebarTab.Diagnostics)
    {
        SelectedTab = SidebarTab.Previews;
    }
}
```
